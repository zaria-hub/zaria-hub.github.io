Smart City – Energy Consumption Monitoring & Anomaly Prediction Platform (Prototype)

Designed and built a full-stack IoT-simulated smart city energy platform that models real-time energy consumption across 30 simulated entities (homes, neighborhood zones, and public infrastructure), combining machine learning forecasting, MQTT-based device simulation, a REST API backend, an administrative web dashboard, and a native Android consumer app with authentication and push-notification-ready alerting.

Key Features:

Time-series forecasting & anomaly detection: Trained individual Prophet models per sensor on 3 years of synthetic historical consumption data (seasonal, weekly, and long-term growth patterns) to predict future usage and flag statistically abnormal growth trends using a dual-criterion approach (fixed threshold + peer-group statistical deviation), validated at 100% detection accuracy against seeded anomalies

Simulated IoT data pipeline over MQTT: A device simulator publishes live per-sensor readings over a secure TLS MQTT connection (HiveMQ Cloud) every 15 seconds; a decoupled subscriber service consumes and persists both a full historical log and a fast-access "latest reading" cache in MongoDB — architected to allow real IoT hardware to replace the simulator without touching the rest of the system

Centralized REST API (FastAPI): Serves live readings, ML predictions, and location metadata to the web dashboard via open endpoints, and exposes JWT-protected endpoints (/auth/login, /me, /me/device-token) scoped per-account for the mobile app, ensuring each household/institution can only access its own data

Admin web dashboard: Multi-page operational interface (overview, per-sensor detail, filterable sensor list, alerts feed) built with vanilla HTML/CSS/JS against the REST API, featuring a custom-designed dark "control room" visual system with a growth-ratio gauge component that visualizes the model's own detection logic

Native Android app (Kotlin): Per-account authentication (admin-provisioned credentials, bcrypt-hashed, JWT sessions) giving each household/institution a dedicated login to view only their own live consumption and forecasted growth, with auto-refresh and a review-oriented (non-punitive) anomaly notice designed to avoid false-blame on households whose usage rises for legitimate reasons

End-to-end systems debugging: Diagnosed and resolved a full stack of real-world integration issues across the pipeline — MongoDB/pymongo type coercion bugs, MQTT broker permission scoping, Android emulator network routing failures (resolved via ADB port forwarding), and a PyJWT package-name collision — using Logcat, server tracebacks, and layered network diagnostics (ping/nc/firewall rules)
